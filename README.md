# AetherDisk

轻量、紧凑的 macOS 原生磁盘分析工具。Swift 6 + SwiftUI / AppKit，Apple Silicon，macOS 14+。

当前版本为 **2.0.0**（构建 `2026112301`），正式包采用 Developer ID 签名、Apple 公证和装订票据。

官网：https://aethernative.com/apps/aetherdisk/
下载：https://github.com/bcblr1993/AetherDisk/releases/latest
更新源：https://aethernative.com/apps/aetherdisk/appcast.xml

正式分发为 Apple Silicon、macOS 14+。源码自行构建的默认产物仍为 ad-hoc 预览包，不能替代正式发行包。

## 功能

- **四种交互式空间分布视图**：磁盘概览支持「旭日图（多环扇区联动）」「树状图（Squarified Treemap）」「分栏树（Miller Columns）」「占比条」自由切换，并提供「按目录」「按类型」「按陈旧度」「按保护」四种配色模式，支持点击选中、再次点击目录快速下钻及 `⌘↑` 返回上一级。
- **三档磁盘友好扫描策略**：设置页与 CLI 支持「节能低 I/O」「均衡并发（推荐）」「极速并发」，利用 Darwin `setiopolicy_np(..., IOPOL_THROTTLE)` 实施线程级磁盘 I/O 限流，并在顶层子目录 $\ge 4$ 时启用有界并发，兼顾大型目录扫描速度与前台 SSD 零干扰。
- **挂载卷切换与外置卷安全隔离**：侧边栏实时展示已挂载卷并支持一键切换分析；外部卷严格锁定为「仅只读分析」，完全禁用清理建议与移入废纸篓入口。
- **APFS 本地快照与废纸篓只读透视**：实时识别卷的弹性可回收空间与 `tmutil listlocalsnapshots` 本地快照清单（仅只读展示，绝不删除或干预系统快照），只读汇总 `~/.Trash` 占用与完整磁盘访问权限状态。
- **纯元数据大文件与疑似重复线索**：跨目录大文件排行按磁盘占用与逻辑大小筛选稀疏文件与陈旧文件；新增「疑似重复大文件线索（仅元数据）」，仅按 $\ge 1\text{ MiB}$ 唯一 inode 的 `(逻辑大小, 扩展名)` 分组提示，不读取文件内容、不计算哈希、不提供批量删除。
- **原生快速预览与拖放分析**：支持通过系统 `QLPreviewPanel`（`⌘Y`）只读快速预览文件；支持直接将真实文件夹拖入窗口发起只读扫描（`lstat` 严格拒绝符号链接与单文件）。
- **多快照趋势对比与工程洞察**：最多保留 10 份本机完整扫描快照，展示多快照占用走势柱状图与连续增长热点；自动识别 Git 与主流语言工程及构建缓存占比，支持 `Command + R` 刷新与 10 列 CSV 安全导出。
- **严格保护与确认后废纸篓清理**：默认不勾选任何缓存；源码、Git 工作树、安装包、签名归档、凭据、聊天备份及自定义保护目录阻止清理；执行前重新校验指纹并显式二次确认，仅移入系统废纸篓。
- **Sparkle 2.10.0 应用内更新**：手动检查、每日自动检查开关、Ed25519 签名更新清单与安装包验证。

## 运行

```sh
swift test --jobs 4
scripts/build-preview.sh
open outputs/AetherDisk.app
```

命令行扫描不启动 GUI，永远只读：

```sh
swift run aetherdisk-scan ~/Downloads --profile balanced --duplicates --volumes
swift run aetherdisk-scan ~/Downloads --json /tmp/aetherdisk-downloads.json --csv /tmp/aetherdisk-downloads.csv
```

默认不会扫描，用户选择位置、拖入真实文件夹或点击扫描后才开始。访问部分受保护的文件夹时，macOS 可能要求授权；权限不足会标记未读取路径，不会当作零占用或完整扫描。可在系统设置中为应用允许完整磁盘访问。

## 清理边界

1. 仅限个人文件夹内、规则识别的真实缓存目录；外部卷严格只分析，无清理入口。
2. 源码扩展名、项目清单、Git 元数据/跟踪文件/未被忽略文件、安装包、应用包、xcarchive、签名材料、聊天备份等会阻止整个候选目录清理。
3. 不跟随符号链接，不跨卷。发现权限遗漏则该候选不可清理。
4. 预览和执行均检查进程占用；执行前重新核对 inode、大小、修改时间、变更时间、硬链接数等目录指纹。计划两分钟后失效且只能使用一次。
5. 构建目录要求真实普通文件清单佐证；受保护的源码/安装包/备份容器内部缓存不清理。Git 校验失败保留文件。
6. 批次先全部校验，再逐项移入系统废纸篓；操作错误立即停止，并报告已完成与失败项。
7. 不会自动清空废纸篓。移入废纸篓通常不会立即释放磁盘空间；实际容量变化另行显示。

这些保护采取保守策略，可能保留本可再生成的依赖源码或测试归档。不是仅根据 `.build`、`build`、`target` 名称整批删除。

## 统计与性能

扫描仅读取文件系统元数据（`open`/`openat` + `getattrlistbulk`/`fstatat`/`fstat`/`lstat`/`statfs`），绝不读取文件内容。按值类型 `(dev, ino)` 对硬链接去重，使用分配块数和逻辑长度分别统计。目录树最多保留 `40,000` 个常规节点（并独立保留 `400` 个缓存候选、`1,500` 个深层大目录及已分配与逻辑大小各前 `200` 个至少 `1 MiB` 的大文件候选），避免为数百万文件建立无界内存树；深入目录时也可在内存保留层直接展开，或针对特定目录发起独立重扫。

APFS 克隆共享、压缩、稀疏文件和其他卷使目录占用不能直接等同于可回收容量。符号链接不计入目标内容，其他卷不遍历。扫描结果包含取消和权限遗漏状态。权限范围不同的两次扫描，其变化可能不具可比性。

历史记录只保存在 `~/Library/Application Support/AetherDisk/Scans`，清理审计账本只保存在 `~/Library/Application Support/AetherDisk/cleanup-audit.json`，均不上传。更新由 Sparkle 负责，不发送系统概况；更新网络请求本身仍会到达配置的更新服务。

## 验证

参见 [docs/VERIFICATION.md](docs/VERIFICATION.md)。原生界面在 Tart `macos27` 运行并由实际窗口生成截图。QA 数据为本次创建的独立测试文件，不使用用户真实聊天数据作为展示素材。

扫描结果是动态文件系统的观测值，不是原子快照。目录在遍历期间变化、跨卷和深度限制会标记部分结果；部分扫描不覆盖完整历史。清理仅移入废纸篓，不永久删除；应用无法对不配合文件协调、持续并发改写或刻意伪装成缓存的任意数据作出零风险保证。重要文件可设置整个项目/发布目录保护，清理前退出相关应用。
